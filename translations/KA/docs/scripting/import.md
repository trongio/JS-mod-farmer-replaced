# იმპორტი
მთელი კოდის ერთ ფაილში შენახვა მალე უმართავი ხდება. 
`import` ინსტრუქციები სხვა ფაილიდან ფუნქციებისა და გლობალური ცვლადების იმპორტის საშუალებას გაძლევს.
აი, როგორ მუშაობს ეს, ერთ ეკრანის სურათზე:
![|x400](ImportsInOnePicture)

აქ `import module2` ასრულებს ფაილს სახელად `module2` და წვდომას გაძლევს მის ყველა გლობალურ ცვლადზე.
შემდეგ იმპორტირებული მოდულის ცვლადებსა და ფუნქციებზე წვდომა `.` ოპერატორით შეგიძლია.
ასე რომ, ამ მაგალითში `module2.print_x()` იძახებს `print_x()`-ს `module2`-ში.

### აქედან იქით კითხვა აღარ გჭირდება

`from` სინტაქსით შეგიძლია იმპორტირებული მოდულის გლობალური ცვლადები გადაიტანო მიმდინარე არეში, სადაც იმპორტის ინსტრუქცია სრულდება.

`from module2 import print_x
print_x()`
`module2`-დან მხოლოდ მითითებული გლობალური ცვლადების იმპორტს აკეთებს.

ან

`from module2 import *
print_x()`
`module2`-დან ყველა გლობალური ცვლადის იმპორტს აკეთებს.

ეს ასევე აკეთებს `module2` ფაილის იმპორტს, მაგრამ `module2` სახელის ცვლადით წვდომის ნაცვლად, `module2`-ის გლობალურ ცვლადებს გაშლის და პირდაპირ ლოკალურ არეში მიანიჭებს.

იმპორტის ეს ფორმა ჩვეულებრივ რეკომენდებული არ არის, რადგან ცუდად მუშაობს, როცა ორი ფაილი ერთმანეთის იმპორტს აკეთებს, და სახელების დამთხვევის გამო შეიძლება შემთხვევით გადაწერო ცვლადები იმ ფაილში, რომელიც იმპორტს აკეთებს. თუ არ იცი, რას აკეთებ, ჯობია `from` სინტაქსს მოერიდო.

# როგორ მუშაობს სინამდვილეში

## მოკლედ
იმპორტი შეიძლება საკმაოდ არაინტუიციური იყოს, მაგრამ პრობლემების უმეტესობას აიცილებ, თუ `import file` სინტაქსს გამოიყენებ `from file import`-ის ნაცვლად და ყველაფერს, რაც გლობალური განსაზღვრება არ არის, ამ ბლოკში ჩასვამ:
`if __name__ == "__main__":`

## იმპორტის გვერდითი ეფექტები
როცა ფაილის იმპორტს პირველად აკეთებ, თამაში მთელ ფაილს ასრულებს და შემდეგ წვდომას გაძლევს ყველა ცვლადზე, რომელიც ამ შესრულებისას განისაზღვრა.
თუ იმავე ფაილის იმპორტს ისევ გააკეთებ, დაბრუნდება პირველი იმპორტისას დაქეშილი მოდული.

ეს ნიშნავს, რომ იმპორტის ინსტრუქციებს შეიძლება გვერდითი ეფექტები ჰქონდეს. თუ იმპორტს უკეთებ ფაილს, რომელიც `harvest()`-ს იძახებს, იმპორტის დროს მართლა მოხდება მოკრეფა. მაგრამ ხელახლა იმპორტისას მოკრეფა აღარ განმეორდება, რადგან ფაილი მხოლოდ ერთხელ სრულდება.

ასეთი გვერდითი ეფექტების თავიდან აცილება `__name__` ცვლადით შეიძლება. ეს ცვლადი ავტომატურად იღებს მნიშვნელობას `"__main__"`, როცა ფაილი პირდაპირ სრულდება, და ფაილის სახელს, როცა ფაილი `import`-ით სრულდება.
კარგ პრაქტიკად ითვლება, რომ ყველა კოდი, რომლის შესრულებაც ფაილის იმპორტისას არ გინდა, ჩასვა `if __name__ == "__main__":` ბლოკში.

Python-ში ფაილის გავრცელებული სტრუქტურაა, როცა კოდი, რომელიც ფაილის გაშვებისას უნდა შესრულდეს, `main()` ფუნქციაშია. ასე ნათლად გაიმიჯნება ლოკალური ცვლადები (განსაზღვრული `main()`-ის შიგნით) და გლობალური ცვლადები, რომელთა იმპორტიც შეიძლება (განსაზღვრული `main()`-ის გარეთ).

`a_global_variable = "global"

def main():
    a_local_variable = "local"
    # do things

if __name__ == "__main__":
    main()`

## იმპორტის ციკლები
რა მოხდება, თუ `a` ფაილი `b` ფაილის იმპორტს აკეთებს, ხოლო `b` ფაილი `a` ფაილის იმპორტს?

`a` ფაილი:
`import b
x = 0`

`b` ფაილი:
`import a
def f():
    print(a.x)`

ეს მშვენივრად იმუშავებს. ვთქვათ, არც ერთი ფაილი ჯერ ჩატვირთული არ არის და ვიღაც სხვა ასრულებს `import a`-ს.

- `a` სრულდება `import b` ხაზამდე.
- `b` სრულდება `import a` ხაზამდე.
- `a` მოდული უკვე არსებობს, მაგრამ `x` მასში არ არის, რადგან მხოლოდ `import b` ხაზამდე მივიდა.
- `b` ნახევრად ჩატვირთული `a` მოდულის მიმართვას ინახავს ცვლადში სახელად `a`.
- `b` ასრულებს `def` ინსტრუქციას და ინახავს `f()` ფუნქციას.
- `a` აგრძელებს შესრულებას და ინიციალიზაციას უკეთებს `x`-ს.

როცა ვინმე `b.f()`-ს გამოიძახებს, ის სწორად დაბეჭდავს `0`-ს, რადგან `a` მოდული, რომლის მიმართვაც `b`-ს აქვს, ახლა უკვე სრულად ჩატვირთულია.

ახლა განვიხილოთ იგივე კოდი `from` სინტაქსით.

`a` ფაილი:
`from b import *
x = 0`

`b` ფაილი:
`from a import *
def f():
    print(x)`

- `a` სრულდება `from b import *` ხაზამდე.
- `b` სრულდება `from a import *` ხაზამდე.
- `a` მოდული უკვე არსებობს, მაგრამ ბოლომდე ჯერ არ შესრულებულა.
- `b` ყველაფერს, რაც ამ მომენტში `a`-შია, საკუთარ გლობალურ არეში გაშლის. ამ დროს `a` არაფერს შეიცავს, რადგან `x = 0` ხაზამდე ჯერ არ მისულა, ამიტომ იმპორტით არაფერი შემოდის.
- `b` ასრულებს `def` ინსტრუქციას და ინახავს `f()` ფუნქციას.
- `a` აგრძელებს შესრულებას და ინიციალიზაციას უკეთებს `x`-ს.

თუ ახლა ვინმე `b.f()`-ს გამოიძახებს, მიიღებს შეცდომას, რომ `x` მიმდინარე არეში არ არსებობს. ეს იმიტომ ხდება, რომ ამჯერად `b`-ს არ აქვს ჯერ კიდევ ჩატვირთვის პროცესში მყოფი `a`-ს მიმართვა და ვერ ხედავს განსაზღვრებებს, რომლებიც იმპორტის შემდეგ დაემატა.
